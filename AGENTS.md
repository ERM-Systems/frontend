# erm-frontend / erm

ERM's SvelteKit 5 rewrite (v4). The git repo root is `erm-frontend/`; all app code and `package.json` live in `erm/`. Run every command from `erm/`.

## Commands

- `npm run dev` — Vite dev server
- `npm run check` — `svelte-kit sync` + svelte-check (run after edits)
- `npm run lint` — `prettier --check . && eslint .`
- `npm run format` — `prettier --write .` (tabs, single quotes, no trailing commas)
- `npm run build` — generates `build/` via `@sveltejs/adapter-node`; `npm start` = `node build`
- No CI workflows exist.

## Config quirks

- There is NO `svelte.config.js`. SvelteKit + adapter config is inline in `vite.config.ts` via `sveltekit({...})`; runes are forced on (`runes: true` via compilerOptions) for all app files. Tailwind is v4 via the `@tailwindcss/vite` plugin — no `tailwind.config.js`.
- `.npmrc` sets `engine-strict=true`; engines require Node >= 22.
- ESLint uses `projectService` (type-aware) on `.svelte`/`.svelte.ts`; a few components opt into `svelte/no-navigation-without-resolve` with `ignoreLinks` — don't use `goto` for them.

## Env

`.env` is gitignored (sample: `.env.example`). Server code reads `$env/dynamic/private`; public vars (`PUBLIC_*`) via `$env/dynamic/public` (e.g. `publicEnv.PUBLIC_TURNSTILE_SITE_KEY`).

- `VITE_INTERNAL_URL` — REQUIRED; base URL of the closed backend. Every server fetch goes to `${VITE_INTERNAL_URL}/...`. Missing it makes features silently 404/return null.
- `BACKEND_PUBLIC_URL` — overrides `VITE_INTERNAL_URL` for the OAuth redirect and some settings when set.
- `ENVIRONMENT` — feature gate: `'staging'` switches the session cookie to `authTokenStaging`; `'affiliates'` 404s the sitemap routes and toggles affiliates UI.
- `TURNSTILE_SECRET_KEY` + `PUBLIC_TURNSTILE_SITE_KEY` (login captcha), optional `BODY_SIZE_LIMIT`, `UMAMI_SCRIPT_URL`/`UMAMI_WEBSITE_ID` (`%analytics%` placeholder replaced in `hooks.server.ts`).

## Architecture

- Pure SSR frontend proxying a PRIVATE backend over HTTP. No direct DB access; the session token cookie (30-day httpOnly `authToken`) is sent as `Authorization: <token>` to `${VITE_INTERNAL_URL}/{guildId}${path}`.
- Backend returns PascalCase JSON (e.g. `body.Roles`). Server fetchers use `TtlCache` + `dedupe` from `src/lib/server/cache.ts` — follow that pattern, don't bypass the cache.
- Auth flow: `/login` POST verifies Turnstile, redirects to `${BACKEND_PUBLIC_URL || VITE_INTERNAL_URL}/Auth/Discord`, backend redirects back to `/auth?token=...`, which sets the cookie. Guarded paths: `/guilds`, `/settings`, `/billing`, `/{guildId}/dashboard|panel` → `/login?returnTo=`.
- Sessions are backed by `.cache/.session-cache.json` (gitignored) with revalidation every 15 min.
- `src/lib/markdown.ts` is the app's own lightweight markdown renderer (used by `Markdown.svelte`, `MessagePreview.svelte`) — NOT mdsvex; no markdown dependency.

## Gotchas

- `src/lib/server/.svelte-kit/` and `src/lib/server/node_modules/` are stray generated/gitignored dirs echoing the repo root. Exclude them from grep/glob results — everything real lives in `src/`.
- Never reintroduce paraglide, playwright, mdsvex, or vitest — they were deliberately removed.
- Svelte 5 runes everywhere; state lives in `*.svelte.ts` modules, no stores.
- The `.opencode`/`.claude` config loads the `@sveltejs/opencode` plugin and the svelte ai-tools marketplace — Svelte docs/tools are available by design.
